# IRIS "성과지표 — 성능지표 및 측정방법" 화면 입력 가이드

> **대상 화면**: 범부처통합연구지원시스템(IRIS) → 과제접수 → 성과지표 탭
> **과제**: (RS-2026-25622037) 디저트 도메인 특화 AI 트렌드 분석·수요예측 엔진 및 단체주문 자동 매칭·랭킹 시스템 개발
> **근거 문서**: [02 §10.1](../docs/02_트렌드분석추천시스템_기획.md)(안건 1 KPI 4종) · [03 §10.1](../docs/03_자연어추천랭킹시스템_기획.md)(안건 2 KPI 5종) · [01 갭분석 §"성능지표 평가 디테일"](../docs/01_TIPS제안서_갭분석및체크리스트.md)

## 1. 이 화면이 뭔가요? (왜 중요한가)

이 화면은 **"이 과제가 성공했는지를 무엇으로, 어떻게 측정할 것인가"** 를 정부에 약속하는 표입니다.

- 여기 적은 숫자(목표치)가 **과제 종료 시 성패 판정 기준**이 됩니다. 못 지키면 실패 판정 위험이 있으므로 **부풀리지 말고, 우리 문서(02·03 §10.1)에 이미 정리된 검증 가능한 수치**를 그대로 씁니다.
- 심사에서도 배점이 큽니다. TIPS 평가의 "개발 실현성(10점)"이 정확히 이 표를 봅니다 — ① 기술 성능을 판단할 수 있는 지표인가 ② 목표치가 적절한가 ③ **평가방법·환경이 구체적인가** ④ **객관적 입증(제3자 공인)이 가능한가** ([01 갭분석](../docs/01_TIPS제안서_갭분석및체크리스트.md) 참조).

화면은 두 부분입니다:

| 화면 영역 | 무엇을 쓰나 |
|---|---|
| **① 결과물의 성능지표** (윗표, 열 9개) | 지표 이름·단위·중요도(비중)·세계/국내 현재 수준·목표치·근거 |
| **② 평가방법 및 평가환경** (아랫표) | ①의 각 지표를 **어떻게(방법)·어디서(환경)** 측정할지 |

## 2. 입력 전 꼭 알아야 할 것 5가지

1. **행 추가는 [성능지표추가] 버튼**으로 합니다. 지표 1개 = 1행. 아래 추천안은 **8행**입니다.
2. **글자 수 제한**: 평가항목·단위 = **100자**, 그 외 칸 = **300자** (화면 빨간 안내문). 아래 초안은 전부 이 제한 안쪽으로 맞춰 두었습니다.
3. **비중(%)의 합계는 100**이 되어야 합니다(아래 추천안: 15+10+10+10+15+15+10+15 = 100).
4. **[임시저장]은 데이터를 검증하지 않습니다**(화면 하단 빨간 경고). 최종확인·제출 전 반드시 **[저장]** 버튼으로 저장하세요.
5. **"세계 최고수준" 칸은 제출 전 반드시 사실 확인**이 필요합니다. 아래 초안에서 `【확인 필요】` 표시가 붙은 수치는 논문·공식 벤치마크 출처를 찾아 확인 후 기재하세요(없으면 "직접 비교 가능한 공표치 없음 + 인접 지표" 방식으로 씁니다 — §5 참조).

## 3. 각 칸(열)이 무슨 뜻인가요? — 완전 초보용

| 칸 이름 | 쉬운 설명 | 우리 과제에서 쓰는 법 |
|---|---|---|
| **평가항목(주요성능)** | 무엇을 잴 건지, 지표의 이름 | 예: "트렌드 성장기 진입 탐지 정확도(정밀도·재현율)" |
| **단위** | 그 숫자의 단위 | 점(0～1), %, %p, 일(day) 등 |
| **비중(%)** | 여러 지표 중 이 지표가 차지하는 중요도. **전체 합 100** | 핵심 R&D 지표에 15, 보조 지표에 10 |
| **세계 최고수준 보유국/보유기관** | 이 기술을 세계에서 제일 잘하는 나라/회사·기관 | 예: "미국/Google" — 없으면 "공표치 없음, 인접 지표 기준" |
| **세계 최고수준 성능수준** | 그들이 내는 성적(숫자 또는 서술) | 예: "범용 영어 NER F1 약 0.93(CoNLL-03)" |
| **연구개발 전 국내 수준** | R&D **하기 전** 국내(=지금 우리/업계)의 방식 | 예: "단순 언급량 이동평균 임계 방식(후행 탐지)" |
| **연구개발 전 국내 성능수준** | 그 방식이 내는 성적 | **백테스팅으로 실측해 기입**([guides/09](../docs/guides/09_트렌드스코어링_백테스팅.md) `compare.py`) — 근거 없는 숫자 금지 |
| **목표 설정근거** | 왜 목표치를 그 숫자로 잡았는지 | 픽미 공동연구 PoC v1 대비 개선폭 + 백테스팅/골든셋으로 검증 가능 ([02 §5.3.1](../docs/02_트렌드분석추천시스템_기획.md)·[03 §6.3](../docs/03_자연어추천랭킹시스템_기획.md)) |
| **목표치** | 과제 끝날 때 달성하겠다는 숫자 | 02·03 §10.1 표의 KPI 그대로 |

> **용어 30초 정리** (02·03 §10.1.1의 비유 재사용)
>
> - **정밀도** = "맞다고 고른 것 중 진짜 맞은 비율" → *그물로 건진 것 중 생선 비율* (헛다리 안 짚기)
> - **재현율** = "실제 정답 중 놓치지 않고 찾은 비율" → *강에 있던 생선 중 건진 비율* (놓치지 않기)
> - **F1** = 정밀도와 재현율의 균형 평균(한쪽만 높여서 못 속이게 하는 점수)
> - **nDCG@10** = 추천 상위 10개의 "순서 채점" 점수(좋은 걸 위에 올렸는가)
> - **%p(퍼센트포인트)** = 절대 격차. 60%→75%면 +15%p
> - **리드타임** = 언론 보도보다 며칠 **먼저** 잡아냈는가

## 4. 추천 성능지표 8종 — 요약표

안건 1(트렌드 엔진) 4종 + 안건 2(매칭·랭킹) 3종 + 공통(환각 통제) 1종. 모두 02·03 §10.1의 확정 KPI에서 그대로 가져온 것.

| # | 평가항목(주요성능) | 단위 | 비중 | 목표치 | 출처 |
|---|---|---|---|---|---|
| 1 | 트렌드 성장기 진입 탐지 정확도(정밀도·재현율) | 점(0～1) | 15 | 각 0.70 이상 | 02 §10.1 난제 1 |
| 2 | 트렌드 조기 탐지 리드타임(언론 보도 대비 선행 일수) | 일 | 10 | 14 이상 | 02 §10.1 난제 1 |
| 3 | 디저트 신조어·신메뉴 탐지 정확도(F1) | 점(0～1) | 10 | 0.80 이상(평균 포착 지연 7일 이내) | 02 §10.1 난제 2 |
| 4 | 멀티소스 융합 트렌드 적중률 개선폭(단일 최량 소스 대비) | %p | 10 | +15 이상 | 02 §10.1 난제 3 |
| 5 | 자연어 질의 핵심 슬롯 추출 정확도(F1) | 점(0～1) | 15 | 0.85 이상(모호 질의 되묻기 적중 0.8 이상) | 03 §10.1 난제 1 |
| 6 | 추천 랭킹 품질 개선율(nDCG@10, 규칙기반 대비) | % | 15 | +20 이상(하드제약 위반 추천율 1% 이하) | 03 §10.1 난제 2 |
| 7 | 전국 업체 카탈로그 중복 병합 정확도 | 점(0～1) | 10 | 0.95 이상(폐업·휴업 오추천율 1% 이하) | 03 §10.1 난제 3 |
| 8 | AI 생성 인사이트·추천설명 사실 오류율 | % | 15 | 1 이하(출처 추적률 100%) | 02 난제 4 · 03 난제 5 공통 |

> **왜 이 8개인가**: 02의 4대 난제·03의 5대 난제 KPI를 IRIS 표 형식(1지표 1행)에 맞게 정리한 것. 03 난제 4(상업 부스트 통제: 보존율 ≥95%)는 *수익화 운영 지표* 성격이라 성능지표 표에서는 제외하고 사업화 계획 쪽에서 다루는 걸 추천(행을 더 쓸 수 있으면 9행으로 추가해도 됨).

## 5. 행별 복붙용 초안 (칸별 전체 텍스트)

각 행의 9개 칸을 그대로 붙여 넣을 수 있게 정리. `【확인 필요】`는 제출 전 출처 검증 필수, `【실측 기입】`은 백테스팅/골든셋 돌린 뒤 숫자를 넣는 자리.

### 행 1 — 트렌드 성장기 진입 탐지 정확도

| 칸 | 입력값 |
|---|---|
| 평가항목 | 트렌드 성장기 진입 탐지 정확도(정밀도·재현율) |
| 단위 | 점(0～1) |
| 비중 | 15 |
| 세계 최고수준 보유국/보유기관 | 미국/Google 【확인 필요】 |
| 세계 최고수준 성능수준 | 검색 급상승 실시간 감지(Google Trends 등)는 급등 발생 "후" 탐지 중심으로, 정점 도래 전 성장기 진입을 예측하는 도메인 특화 지표의 공표 성능치는 없음. 인접 지표로 대체 서술 【확인 필요】 |
| 연구개발 전 국내 수준 | 언급량 단순 임계·이동평균 기반 사후 탐지(광고성 급등 오탐, 정점 후행 포착) |
| 연구개발 전 국내 성능수준 | 동일 검증셋 백테스팅 실측치 기입 예정 【실측 기입 — guides/09 compare.py】 |
| 목표 설정근거 | 픽미 공동연구로 기구축한 트렌드 점수 대시보드(작동 PoC v1)를 베이스라인으로, S-curve 피팅+1·2차 미분 모멘텀+과거 곡선 시계열 유사도 기법의 개선폭으로 설정. 흥망이 종료된 과거 사례(약과·두바이초콜릿·소금빵 등) 콜드스타트 백테스팅으로 사전 검증 가능한 수치임 |
| 목표치 | 정밀도·재현율 각 0.70 이상 |

### 행 2 — 트렌드 조기 탐지 리드타임

| 칸 | 입력값 |
|---|---|
| 평가항목 | 트렌드 조기 탐지 리드타임(주요 언론 보도 시점 대비 선행 일수) |
| 단위 | 일 |
| 비중 | 10 |
| 세계 최고수준 보유국/보유기관 | 해당 공표치 없음(도메인 특화 선행지표) 【확인 필요】 |
| 세계 최고수준 성능수준 | 식품·유통 트렌드 예측 리포트(미국 등)는 시즌 단위 예측 중심으로, 개별 아이템의 보도 대비 선행 일수를 공표하는 사례 없음 |
| 연구개발 전 국내 수준 | 운영자가 뉴스·SNS를 눈으로 모니터링(보도 후 인지) |
| 연구개발 전 국내 성능수준 | 보도 시점과 동시 또는 후행(리드타임 0일 이하) |
| 목표 설정근거 | 14일은 입점사가 원재료 발주·생산 준비·B2B 제안까지 실행할 수 있는 최소 리드타임(02 §5.3.2). 과거 흥망 종료 사례의 시계열로 보도일 대비 최초 성장신호 검출일을 역산(lead_time 함수)해 측정 가능 |
| 목표치 | 평균 14일 이상(반짝유행 오탐률 20% 이하 병행 관리) |

### 행 3 — 신조어·신메뉴 탐지 F1

| 칸 | 입력값 |
|---|---|
| 평가항목 | 디저트 도메인 신조어·신메뉴 탐지 정확도(F1) |
| 단위 | 점(0～1) |
| 비중 | 10 |
| 세계 최고수준 보유국/보유기관 | 미국/Google·Meta 등 【확인 필요】 |
| 세계 최고수준 성능수준 | 범용 개체명인식(NER)은 영어 표준 벤치마크(CoNLL-03) 기준 F1 약 0.93 수준. 단 한국어 디저트 신조어·합성어(예: 크룽지)는 범용 모델이 누락하는 영역으로 직접 비교 공표치 없음 【확인 필요 — 수치·출처 재검증】 |
| 연구개발 전 국내 수준 | 범용 NER·고정 키워드 사전 매칭(사전에 없는 신조어 누락) |
| 연구개발 전 국내 성능수준 | 신조어 신규 탐지 재현율 낮음 — 동일 검증셋 실측치 기입 예정 【실측 기입】 |
| 목표 설정근거 | 픽미 공동연구 키워드 분석(07 §2)을 선행 자산으로, 빈도 급증 후보 자동 발굴+LLM 보정+도메인 사전 자동 성장 3단 기법의 목표치. 과거 신조어 등장 사례를 라벨링한 검증셋으로 측정 |
| 목표치 | F1 0.80 이상, 평균 포착 지연 7일 이내 |

### 행 4 — 멀티소스 융합 적중률 개선폭

| 칸 | 입력값 |
|---|---|
| 평가항목 | 멀티소스 융합 트렌드 적중률 개선폭(단일 최량 소스 대비) |
| 단위 | %p |
| 비중 | 10 |
| 세계 최고수준 보유국/보유기관 | 해당 공표치 없음(자사 상대 개선폭 지표) |
| 세계 최고수준 성능수준 | 멀티소스 융합 트렌드 예측의 표준 공개 벤치마크 부재. 본 지표는 동일 검증셋에서 자체 측정하는 상대 개선폭임 |
| 연구개발 전 국내 수준 | 단일 소스 의존 또는 단순 합산(소스 신뢰도·광고 편향 미반영) |
| 연구개발 전 국내 성능수준 | 가장 적중률 높은 단일 소스의 백테스팅 실측치 기입 예정 【실측 기입】 |
| 목표 설정근거 | 비교 상대를 여러 소스의 평균이 아닌 "가장 잘 맞히는 단일 소스"로 설정 — 최량 소스도 못 이기면 융합의 의미가 없으므로 융합의 실익을 정직하게 증명하는 기준(02 §10.1.1). 소스 신뢰도 가중+이상치 필터+교차검증 보정 기법으로 달성 |
| 목표치 | 단일 최량 소스 대비 적중률 +15%p 이상 |

## 6. "평가방법 및 평가환경" (아랫표) 초안

윗표의 평가항목별로 1행씩. **"어떻게 재나(방법) + 어디서/무엇으로 재나(환경)"** 를 구체적으로 쓸수록 점수에 유리하고, **"제3자 공인 가능"** 한 줄이 들어가면 더 좋습니다(01 갭분석: 객관적 입증 항목).

| 평가항목(주요성능) | 평가방법 | 평가환경 |
|---|---|---|
| 행 1·2·4 (트렌드 탐지·리드타임·융합) | 흥망이 종료된 과거 트렌드 사례(약과·두바이초콜릿·소금빵 등)로 검증셋을 구성한 **콜드스타트 백테스팅**. 동일 검증셋에서 베이스라인(언급량 이동평균 임계)과 자체 기법(S-curve+모멘텀+시계열 유사도)을 나란히 산출해 정밀도·재현율·리드타임·적중률 개선폭 측정 | 자체 백테스팅 환경(수집 파이프라인+평가 코드). 검증셋·코드·결과표를 재현 가능하게 보관해 제3자 검증(공인시험기관 성적서 등)에 대응 가능하도록 관리 |
| 행 3 (신조어 F1) | 과거 신조어·신메뉴 등장 사례를 사람이 라벨링한 검증셋으로 탐지 F1·포착 지연 측정. 범용 NER·사전 매칭 베이스라인과 동일 셋 비교 | 상동(자체 평가 환경, 라벨링 가이드라인·검증셋 보관) |
| 행 5·6·7 (슬롯·랭킹·병합) | 서울 1～2개 구·핵심 카테고리 한정 **골든셋 평가**: 대표 자연어 질의 50～100개와 정답 업체 셋을 사람이 라벨링하고, 슬롯 F1·nDCG@10·하드제약 위반율·병합 정확도·폐업 오추천율을 베이스라인(키워드+단일 임베딩)과 비교. 추천 만족도는 블라인드 사람평가 병행. 영업상태는 공공데이터(인허가) 대조 | 자체 PoC 환경(전국 카탈로그 수집·정규화 파이프라인+채팅형 MVP 데모). 골든셋·평가코드·결과표 재현 가능 보관, 제3자 공인 대비 |
| 행 8 (사실 오류율) | 생성된 인사이트·추천 설명 표본(N건)을 원천 데이터(계산 수치·DB 영업정보)와 전수 대조해 사실 오류율 산출. 문장별 출처(citation) 부착 여부는 자동 검사로 추적률 100% 확인 | RAG 파이프라인(LangChain·LangGraph) 운영 환경 + 자동 citation 검사 스크립트. 대조 로그 보관 |
